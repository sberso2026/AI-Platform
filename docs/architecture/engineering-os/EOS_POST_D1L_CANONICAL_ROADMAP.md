# EOS Post-D1L Canonical Roadmap

## Decision

D1L remains closed with limitations. Its closeout left the next Structural phase unnamed. This decision names that phase. It does not implement it.

The repeated repository subject after D1L is D1M, described as CAD or BIM intelligence and recorded as not absorbed. D1N remains concept-to-detailed orchestration and is not next. No other Structural phase is recorded between them.

## D1M

The canonical name is CAD OR BIM INTELLIGENCE. Its purpose is to govern Structural references to CAD or BIM model identity, exact revision, provenance, and authority. A model reference is not engineering validation, design approval, or certification.

The first phase is EOS-D1M-0-CAD-OR-BIM-INTELLIGENCE-ARCHITECTURE. Its type is CAD or BIM intelligence architecture. It is authorized and not ready, because the architecture has not been written. The track remains not started. The historical status that D1M was not absorbed stays unchanged on the earlier roadmap.

The architecture phase is to define artifact and source identity, exact revision, provenance, authority, Structural target linkage, object identity, geometry and semantic evidence, coordinates, units, axes, relationships, the file and API boundary, which formats are supported, immutability, change detection, fingerprints, the digital thread, human review, AI limits, reuse of D1K, use as D1L evidence, the handoff to D1N, and the boundary with D9. No industry format is authorized by this decision. The architecture phase must name any supported format explicitly.

## Boundaries

D1M does not absorb D1N. Concept-to-detailed orchestration stays with D1N. D1M does not absorb D9. Multidisciplinary reasoning, global dependency reasoning, and global cycle detection stay with D9. D1M does not create a second cross-discipline integration system. If a CAD or BIM artifact carries cross-discipline information, a later design must connect it through D1K. D1K internal integration and D1K intelligence remain not ready.

D1M does not change a D1L certification decision. A future model reference may become certification evidence only through the existing certification chain. D1M cannot grant certification. Presence of a model is not engineering validation. A successful parse is not engineering correctness.

D1M does not author CAD or BIM models, replace a CAD or BIM product, edit geometry, produce drawings autonomously, transform a model silently, coordinate every discipline, or approve a design. It does not start a connector to a vendor, a document store, or a model host. It does not start a runtime.

## Preserved state

D1L stays complete with limitations. Certification runtime and certification authority stay ready. Certification eligibility stays unsatisfied. The historical D1L status on the earlier roadmap stays not started. D1G live validation, engineer validation, conformance, and certified-solver status stay unmet. Concrete C10 review, D1F human review, D1H validation, D1I validation and conformance, D1J validation and conformance, and unavailable D1J concrete parameter semantics stay open. GA security debt still blocks general availability. The structural pack stays incomplete. D2 through D9 stay not started. No database schema changes. No dependency is added.

## Next phase

The next phase is EOS-D1M-0-CAD-OR-BIM-INTELLIGENCE-ARCHITECTURE. It starts from the commit that records this canonicalization. This decision does not execute it.
