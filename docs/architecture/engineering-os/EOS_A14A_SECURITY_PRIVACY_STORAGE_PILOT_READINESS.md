## Object-storage architecture

| Decision | Value |
|---|---|
| OBJECT_STORAGE_PROVIDER | SUPABASE_STORAGE |
| Bucket | `engineering-artifacts` (private, dedicated; not PI `engineering-documents`) |
| PUBLIC_BUCKET_REQUIRED | NO |
| Isolation | server object key `eos/artifacts/{tenant}/{workspace}/{project}/{artifact}/v{n}` |
| Access | server-mediated after EOS authorization; RESTRICTIVE storage policy denies anon/authenticated bucket access |
| Signed download | ≤300s, single object, not stored as canonical reference |
| New writes | OBJECT_STORAGE via `RoutingArtifactBinaryStore` when `EOS_ARTIFACT_OBJECT_STORAGE !== "0"` |
| Legacy | `LegacyRelationalArtifactBinaryStore` remains readable |
| Dual-write | NO (new object writes clear `contentBase64` on the metadata row; column retained) |
| Purge | NO (`content_base64` not dropped) |

Backup/retention: staging Postgres is provider-backed (Supabase). Object durability is Supabase Storage replication; this is not EOS artifact versioning. Full disaster-recovery rehearsal is A14B.

Malware integration: returned/user-supplied bytes reuse `@rtb/engineering-review` `scanWithEstablishedScanner`. Fresh EOS-generated bytes are a trusted generation boundary and are not treated as inbound untrusted files; package/integrity validation still applies. Metadata-only external references are not scanned.

## Storage policies

- Filename is never object identity.
- Caller-supplied `tenantId` / `workspaceId` / `objectKey` / `storageKind` are rejected.
- Cross-tenant, cross-workspace, cross-project, and anonymous object access deny.
- Size limits are **controlled-pilot configuration**, not universal EOS limits: generated 25 MiB, returned 15 MiB, template 10 MiB, scan timeout 8s, signed URL 300s.

## Migration rehearsal

Fixture algorithm (MemoryObject + generated XLSX/DOCX/PPTX): decode legacy bytes → verify SHA-256/size → server object key → put → verify → switch pointer → leave `content_base64` → download via ArtifactBinaryStore → remigrate (idempotent) → inject write failure (remain LEGACY_RELATIONAL) → rollback without purge.

Staging SQL `20261001210000_eos_a14a_artifact_object_storage.sql` creates the private bucket and `engineering_artifact_storage_migrations` ledger. Inventory selects metadata only; `content_base64` is never logged.

## Malware architecture

Reuse Review ClamAV HTTP scanner (`RTB_REVIEW_CLAMAV_URL`). States: CLEAN, INFECTED, SCAN_FAILED, SCANNER_UNAVAILABLE, TIMEOUT, PENDING_SCAN.

Local developer ClamAV does not satisfy HOSTED_MALWARE_SCAN. If the hosted URL is unset, returned uploads fail closed (`MALWARE_SCAN_FAILED` / `SCANNER_UNAVAILABLE`). EICAR is rejected. Timeout fail-closes. Profile A therefore **prohibits returned binary uploads** until a live hosted scanner is proven.
