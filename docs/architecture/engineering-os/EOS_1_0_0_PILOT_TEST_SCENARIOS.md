# EOS 1.0.0 pilot test scenarios

Path: docs/architecture/engineering-os/EOS_1_0_0_PILOT_TEST_SCENARIOS.md

Use only public, synthetic, anonymised, personally owned, or company-approved data. These scenarios are not a production smoke certificate. They run after v1.0.0 is the deployed revision.

1. Engineering knowledge retrieval. Ask a general reinforced-concrete cover question that cites a public standard concept. Confirm the answer identifies its sources and does not claim project approval.

2. Engineering document review. Upload a synthetic one-page calculation memorandum. Start a pre-issue review. Confirm findings are assistance and the run is stored in the same workspace.

3. Requirement and change impact. Record a synthetic requirement and a one-line change. Open the impact view. Confirm it does not approve the change.

4. Decision traceability. Record a synthetic option and a human decision with a rationale. Confirm the decision shows the person, the time, and the release under test.

5. Cross-discipline interface review. Describe a synthetic structural-to-mechanical interface. Confirm the record stays in the workspace and does not write the other discipline's source of truth.

6. Engineering assistant. Ask the assistant a synthetic question. Stop the AI provider or use a known unavailable configuration in a non-production check. Confirm the result is a controlled failure, not an invented engineering approval.

For each scenario record the user, workspace, feature, time, and release 1.0.0. A second workspace user must be unable to open the first workspace's upload. An unauthenticated request for the file must be denied.
