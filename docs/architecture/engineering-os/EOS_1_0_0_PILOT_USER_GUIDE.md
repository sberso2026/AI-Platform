# EOS 1.0.0 pilot user guide

Path: docs/architecture/engineering-os/EOS_1_0_0_PILOT_USER_GUIDE.md

RTB Engineering OS 1.0.0 assists engineering analysis, review, information retrieval, and decision support. Outputs that need professional judgement, approval, or certification must be reviewed by an appropriately qualified person. General availability is not project certification, regulatory approval, or professional sign-off.

The v1.0.0 pilot is not open for invitations until the deployment record says the production pilot is ready. The steps below apply after that point.

Accept an invitation from the mail the administrator sends. Open the link, set a password, and complete MFA if the sign-in flow asks for it. Do not create an organisation from a public signup page. Signup is not the pilot entry.

After sign-in, open the workspace named in the invitation. Create a pilot project only with data the data notice allows: public, synthetic, anonymised, personally owned, or company-approved. Do not upload confidential employer or client data without organisational approval.

Core workflows, using that permitted data:

- Ask for engineering knowledge and check the cited sources.
- Run a document review and read the findings as assistance.
- Record a requirement or change and inspect the impact statement.
- Record a decision and its rationale.
- Review a cross-discipline interface as context, not as approval.
- Use the engineering assistant and treat its answer as support, not as a certified result.

Feedback categories to send to the pilot administrator until a single in-product form is deployed: useful or not useful; technically correct, partially correct, incorrect, or unable to verify; report a bug, report an engineering issue, suggest an improvement, or request a capability. Include the workspace, the feature, and that the release is 1.0.0. Do not attach another organisation's data.

To leave the pilot, ask the administrator to remove the account. Removal is an administrator action, not a self-service public deletion control in this guide.

Severity, for what you report: P0 is a security, tenant-isolation, or critical engineering-safety issue. P1 is a major functional or engineering-governance defect. P2 is a material workflow problem. P3 is a minor bug or enhancement. P0 and P1 stop the affected use until an administrator confirms otherwise. No numeric response-time promise is made.
