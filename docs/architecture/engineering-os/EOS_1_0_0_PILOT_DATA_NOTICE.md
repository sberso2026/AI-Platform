# EOS 1.0.0 pilot data notice

Path: docs/architecture/engineering-os/EOS_1_0_0_PILOT_DATA_NOTICE.md

This notice is for the invite-only RTB Engineering OS 1.0.0 pilot. The v1.0.0 release is not the revision currently served at the existing pilot hostname. Do not treat that hostname as this release.

Informal pilot users must not upload confidential employer, client, or project information unless their organisation has authorized its use.

Allowed data for the initial controlled pilot is public information, synthetic information, anonymised information, personally owned information, and company-approved information.

EOS stores account identity, workspace membership, and the project records a user chooses to create, including documents, reviews, decisions, and files placed in that workspace. Access is by authentication and workspace membership. Workspace isolation is a technical control. It is not a promise of zero data risk, government certification, or a completed GDPR certification.

Where an AI provider is enabled, prompts and selected engineering context can be sent to that provider to produce assistance. AI output is not an engineering approval. If the provider is unavailable, the governed failure mode is a controlled error, not a fabricated approval.

Retention follows the existing platform records. Deletion or removal is requested through the pilot administrator. This notice does not set a new retention period.

Support is the pilot administrator and the platform on-call path in the operations handoff. This notice does not create a legal-compliance claim.
