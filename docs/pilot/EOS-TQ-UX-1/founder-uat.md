# EOS-TQ-UX-1 Founder UAT

Use a clean TQ equivalent to the TQ-006 founder scenario on Preview after this SHA is deployed. Do not use Chevron/KJV sample data.

## Path

1. Engineer opens Technical Queries → New Technical Query.
2. Enters Query / Information Required.
3. Enters Response Due Date.
4. Enters Suggested Solution (initiator proposal).
5. Links or uploads a reference attachment.
6. Confirm Initiator shows the authenticated human name (not a UUID).
7. Assign Action By from the directory selector.
8. Review the pre-submit summary → Submit Technical Query.
9. Confirmation shows number, Action By, due, status, and next-step copy.
10. TQ appears in the register.
11. Action By opens My Actions and sees the TQ.
12. Action By opens the TQ.
13. Original query is read-only after submit.
14. Action By drafts Client / Technical Response.
15. Evidence can be linked.
16. Submit Response.
17. Initiator sees Response Submitted / review next action.
18. Initiator accepts or requests clarification.
19. Link a required follow-up action.
20. Close only after accept + closeout checklist.
21. History tab shows the audit trail.
22. Print view contains the complete record.
23. No raw UUID visible in the UI.
24. Cross-tenant user cannot open the TQ.
25. Unauthorized user cannot mutate response/closeout.
